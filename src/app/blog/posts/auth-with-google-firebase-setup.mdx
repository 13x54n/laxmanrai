Building modern web apps often involves integrating easy-to-use and secure auth systems. Firebase makes this process simple with pre-built providers like Google, GitHub, and Facebook. In this guide, we’ll focus just on **Google Authentication**.

***

### Step 1: Create a Firebase Project

Head over to the [Firebase Console](https://console.firebase.google.com/) and create a new project.  
You don’t need to enable Firebase Hosting — we’ll only use Firebase for authentication in this setup.

Once the project is ready:
- Go to **Build → Authentication**
- Click **Get Started**
- Choose **Google** as a sign-in provider
- Enable it and save your settings

> 💡 During local development, you don’t need to set up authorized domains. Firebase allows sign-ins on `localhost`. But for production, you’ll need to add your domain to the authorized whitelist.

Include a screenshot of this setup process — save it in your project’s `public` folder.

### Step 2: Configure Firebase in Your App

Next, create a `firebase.ts` file inside your `lib` or `src` directory. This file initializes Firebase with your app’s configuration details.

```typescript
// Import the functions you need from the SDKs you need
import { initializeApp } from "firebase/app";
import { getAuth } from "firebase/auth";

// Your web app's Firebase configuration
// Trim values to avoid INVALID_ARGUMENT from extra whitespace
const firebaseConfig = {
  apiKey: process.env.NEXT_PUBLIC_FIREBASE_API_KEY?.trim(),
  authDomain: process.env.NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN?.trim(),
  projectId: process.env.NEXT_PUBLIC_FIREBASE_PROJECT_ID?.trim(),
  storageBucket: process.env.NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET?.trim(),
  messagingSenderId: process.env.NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID?.trim(),
  appId: process.env.NEXT_PUBLIC_FIREBASE_APP_ID?.trim(),
  measurementId: process.env.NEXT_PUBLIC_FIREBASE_MEASUREMENT_ID?.trim(),
};

// Initialize Firebase
const app = initializeApp(firebaseConfig);
export const auth = getAuth(app);
```

> ✅ Be sure to replace each environment variable with your own Firebase project values from the **Project Settings** page.

***

### Step 3: Create the Authentication Library

To keep authentication logic clean and reusable, let’s make a simple helper library to handle sign-in, sign-out, and user state subscriptions.

Create a new file `auth.ts` under `lib`:

```typescript
import {
  GoogleAuthProvider,
  signInWithPopup,
  signOut as firebaseSignOut,
  onAuthStateChanged,
  User,
} from "firebase/auth";
import { auth } from "./firebase";

const googleProvider = new GoogleAuthProvider();

export async function signInWithGoogle() {
  return signInWithPopup(auth, googleProvider);
}

export async function signOut() {
  return firebaseSignOut(auth);
}

export function subscribeToAuthState(callback: (user: User | null) => void) {
  return onAuthStateChanged(auth, callback);
}
```

This handles everything related to Firebase’s `auth` module — creating a provider, signing users in/out, and observing changes in their auth state.

***

### Step 4: Create an Auth Provider (React Context)

Now, let’s set up a **React Context Provider** to keep authentication state available throughout your app.

Create a new file `AuthProvider.tsx`:

```typescript
"use client";

import {
  createContext,
  useContext,
  useEffect,
  useState,
  type ReactNode,
} from "react";
import type { User } from "firebase/auth";
import { subscribeToAuthState } from "@/lib/auth";

type AuthContextValue = {
  user: User | null;
  loading: boolean;
};

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const unsubscribe = subscribeToAuthState((user) => {
      setUser(user);
      setLoading(false);
    });
    return unsubscribe;
  }, []);

  return (
    <AuthContext.Provider value={{ user, loading }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const context = useContext(AuthContext);
  if (context === undefined) {
    throw new Error("useAuth must be used within an AuthProvider");
  }
  return context;
}
```

Wrap your app (usually inside `_app.tsx` or `layout.tsx`) with `AuthProvider`.  
This ensures that `useAuth()` works in any component — giving you access to the current user and a `loading` state.

***

### Step 5: Connect It All in the UI

You can now implement buttons and conditional UI like so:

```tsx
import { signInWithGoogle, signOut } from "@/lib/auth";
import { useAuth } from "@/components/AuthProvider";

export default function LoginButton() {
  const { user, loading } = useAuth();

  if (loading) return <p>Loading...</p>;
  if (!user) return <button onClick={signInWithGoogle}>Sign in with Google</button>;

  return (
    <div>
      <p>Welcome, {user.displayName}</p>
      <button onClick={signOut}>Sign out</button>
    </div>
  );
}
```

## Step 6: Integrate with a Next.js App Router Page

Now that Firebase and your `AuthProvider` are wired up, let’s see how this looks in a real Next.js (App Router) setup.

### Wrap your app with `AuthProvider`

In `app/layout.tsx`, wrap the root layout with `AuthProvider` so that auth state is available everywhere:

```tsx
// app/layout.tsx
import "./globals.css";
import type { ReactNode } from "react";
import { AuthProvider } from "@/components/AuthProvider";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <AuthProvider>
          {children}
        </AuthProvider>
      </body>
    </html>
  );
}
```

This ensures any route can call `useAuth()` to read the current user and loading state.

***

### Create a dedicated login page

Create a simple login page at `app/login/page.tsx` that uses your `signInWithGoogle` function:

```tsx
// app/login/page.tsx
"use client";

import { signInWithGoogle } from "@/lib/auth";
import { useAuth } from "@/components/AuthProvider";
import { useRouter } from "next/navigation";

export default function LoginPage() {
  const { user, loading } = useAuth();
  const router = useRouter();

  // If already logged in, redirect to home (or dashboard)
  if (!loading && user) {
    router.push("/");
  }

  return (
    <main className="flex min-h-screen items-center justify-center">
      <div className="w-full max-w-sm rounded-lg border p-6 shadow-sm">
        <h1 className="mb-4 text-xl font-semibold">Sign in</h1>

        {loading ? (
          <p>Checking session...</p>
        ) : (
          <button
            onClick={async () => {
              try {
                await signInWithGoogle();
                router.push("/");
              } catch (error) {
                console.error(error);
                alert("Failed to sign in with Google");
              }
            }}
            className="w-full rounded bg-blue-600 px-4 py-2 text-white hover:bg-blue-700"
          >
            Continue with Google
          </button>
        )}
      </div>
    </main>
  );
}
```

This page:

- Shows a “Checking session…” state while auth initializes.  
- Redirects an already-signed-in user away from `/login`.  
- Calls `signInWithGoogle` and redirects on success.

### Protect a page (simple client-side guard)

For many apps, you’ll want to restrict certain routes (e.g. `/dashboard`) to authenticated users only. A straightforward way is to use the `useAuth` hook in your page and redirect if there’s no user.

```tsx
// app/dashboard/page.tsx
"use client";

import { useAuth } from "@/components/AuthProvider";
import { useRouter } from "next/navigation";
import { useEffect } from "react";
import { signOut } from "@/lib/auth";

export default function DashboardPage() {
  const { user, loading } = useAuth();
  const router = useRouter();

  useEffect(() => {
    if (!loading && !user) {
      router.replace("/login");
    }
  }, [loading, user, router]);

  if (loading || !user) {
    return <p>Loading dashboard...</p>;
  }

  return (
    <main className="p-6">
      <header className="mb-4 flex items-center justify-between">
        <h1 className="text-2xl font-semibold">Dashboard</h1>
        <div className="flex items-center gap-3">
          <span className="text-sm text-gray-700">
            {user.displayName ?? user.email}
          </span>
          <button
            onClick={async () => {
              await signOut();
              router.push("/login");
            }}
            className="rounded bg-gray-800 px-3 py-1 text-sm text-white hover:bg-gray-900"
          >
            Sign out
          </button>
        </div>
      </header>

      <section>
        <p>Welcome to your private dashboard!</p>
      </section>
    </main>
  );
}
```

What’s happening here:

- While `loading` is true, we show a loading state.  
- Once `loading` is false, if `user` is `null`, we redirect to `/login`.  
- If a user exists, we render the dashboard and expose a **Sign out** button.

### Optional: Show auth state in the main navigation

You can also surface the user state in a global header component:

```tsx
// components/Header.tsx
"use client";

import Link from "next/link";
import { useAuth } from "@/components/AuthProvider";
import { signOut } from "@/lib/auth";

export function Header() {
  const { user, loading } = useAuth();

  return (
    <header className="flex items-center justify-between border-b px-6 py-3">
      <Link href="/" className="font-semibold">
        My App
      </Link>

      {loading ? (
        <span className="text-sm text-gray-500">Loading...</span>
      ) : user ? (
        <div className="flex items-center gap-3 text-sm">
          <span>{user.displayName ?? user.email}</span>
          <button
            onClick={async () => {
              await signOut();
            }}
            className="rounded bg-gray-900 px-3 py-1 text-white"
          >
            Sign out
          </button>
        </div>
      ) : (
        <Link
          href="/login"
          className="rounded bg-blue-600 px-3 py-1 text-sm text-white"
        >
          Sign in
        </Link>
      )}
    </header>
  );
}
```

Then include `<Header />` in your `RootLayout` above `{children}`.

### Wrapping Up

With just a few files, you now have Google authentication fully working in a React (or Next.js) project using Firebase.  
Firebase handles the heavy lifting for you — simplifying OAuth flows, token management, and cross-session state.

Once ready for production, be sure to:
- Add your domain to **Authorized Domains** under Authentication settings.
- Use environment variables for all Firebase keys.
- Test in both development and production modes.
